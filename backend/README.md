# backend/

منطق الخدمات: التحقق من التوفر، إصدار عروض السعر، إنشاء الطلبات، التحقق من
الدفع، Idempotency، وتفويض الإدارة، وآلة حالات الطلب، وسجل التدقيق.

هنا **بس** يُستخدم مفتاح الخدمة (`SERVICE_ROLE_KEY`) في الإنتاج. كل عملية
حساسة تمرّ من هنا.

## قواعد مفروضة في الكود نفسه
1. **مستحيل سعر بيع حقيقي من تكلفة وهمية** — بنمرّ على جسر المزوّد، والرفض
   صريح (`MOCK_NOT_A_REAL_PRICE`) من غير أي تجاوز.
2. **المالك الحقيقي هو العميل** — بيانات الشركة/الموزّع مرفوضة كمالك.
3. **مفيش تسجيل قبل دفع مُتحقَّق منه** — آلة الحالات بتمنع الطفرة دي.
4. **مفيش تسريب تكلفة أو هامش** — بنرجّع `clientQuote` بس (بدون `snapshot`).
5. التنفيذ بيعيد فحص التوفر والتكلفة **لحظة التسجيل** (مش من الـcache).
6. كل عملية حسّاسة بتتسجّل في سجل التدقيق (Append-only).
7. **سجلات السلطة (NS · CAA) ممنوعة من مسار تعديل سجلات الـzone** — الخدمة
   بترفضهم قبل ما يوصلوا للمزوّد، وليهم مسار الـNameservers بس.

## الملفات
| الملف | الدور |
|---|---|
| `lib/service.js` | التنسيق الكامل: بحث · عرض · طلب · دفع · تنفيذ · تجديد · تحويل · DNS (الـNameservers وسجلات الـzone) |
| `lib/orders.js` | آلة حالات الطلب والانتقالات المسموحة |
| `lib/idempotency.js` | نفس المفتاح + نفس الطلب = نفس النتيجة، والاختلاف = `IDEMPOTENCY_CONFLICT` |
| `lib/payments.js` | مزوّد دفع وهمي + تحقّق HMAC-SHA256 من توقيع الإشعار (Web Crypto) |
| `lib/authz.js` | فصل الصلاحيات: العميل يشوف طلباته بس |
| `lib/audit.js` | سجل تدقيق للكتابة فقط |
| `lib/errors.js` | رموز أخطاء ثابتة + حالة HTTP المناسبة |
