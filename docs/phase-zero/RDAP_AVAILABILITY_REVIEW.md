# مراجعة محرك التوفر (RDAP) — Migo Domains

## التصحيح الجوهري

- **ممنوع** استخدام `rdap.org` كمصدر وحيد.
- **ممنوع** اعتبار حد طلباته (10/10ث) حدًا عالميًا.
- RDAP **وسيلة مساعدة للتحقق من حالة التسجيل، ومش مصدرًا لتسعير الدومينات.**
- **المرجع النهائي قبل التسجيل = Registrar Availability API.**

## التصميم الصحيح

| المطلوب | التفصيل |
|---|---|
| قراءة Bootstrap Data الرسمية | ملف bootstrap من IANA (RFC 9224) لربط كل امتداد بسيرفر RDAP المختص |
| تحديد السيرفر المختص | لكل امتداد سيرفره، مش نقطة وسطى واحدة |
| HTTP Status Codes | 200 مسجّل · 404 غير موجود (مش دليل توفر) · 429 Rate-Limited · 5xx خطأ مصدر |
| Redirects | اتباع إعادة التوجيه |
| Rate Limits | احترام حدود كل سيرفر على حدة + Back-off |
| Timeout | حد زمني لكل طلب، والنتيجة `UNKNOWN` عند الفشل |
| Cache | مدة صلاحية مناسبة لكل نتيجة، مع تسجيل وقت الفحص |
| امتدادات بلا RDAP | التحويل لمسار بديل، أو `UNKNOWN` |
| منع الاستنتاج من 404 | 404 لا يعني «متاح» |
| تسجيل المصدر والوقت | كل نتيجة تحمل مصدرها ووقت آخر تحقق |
| UNKNOWN عند غياب الدليل | بلا دليل كافٍ → `UNKNOWN` |

## حالات النتيجة

`AVAILABLE_CONFIRMED` · `REGISTERED` · `PREMIUM` · `RESERVED` · `RESTRICTED` · `UNKNOWN` · `PROVIDER_ERROR` · `MANUAL_REVIEW`

## قواعد الاستعلام

1. مصدر موثوق أكّد التسجيل → اعرض «مسجّل».
2. عدم ظهور سجل → **لا** اعرض «متاح» تلقائيًا.
3. استخدم أكثر من مصدر عند الحاجة.
4. اعرض وقت آخر تحقق.
5. اعرض المصدر داخليًا.
6. عدم استجابة المصدر → `UNKNOWN`.
7. منع التلاعب بطلبات البحث.
8. Rate Limiting و Caching مناسبين.
9. **لا** اعتماد على نتيجة مخزّنة قديمة عند تسجيل حقيقي.

## قيود RDAP المعروفة (من المصادر)

- لا يوجد RDAP لنسبة من الـ ccTLD.
- 404 قد يعني Premium أو Reserved أو Sunrise أو Redemption.
- سيرفرات الريجستري تفرض حدودها الخاصة على IP (أحيانًا منخفضة جدًا).
- RDAP لا يعطي سعرًا إطلاقًا.

## القيد في بيئتنا

الإنترنت مقفول من بيئة التشغيل → اختبار RDAP الحقيقي مستحيل من هنا. التنفيذ والاختبار على سيرفر، أو بعد فتح اتصال لنطاقات محددة بموافقة.
