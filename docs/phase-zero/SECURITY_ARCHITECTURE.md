# معمارية الأمان — Migo Domains

**الحالة: NOT_IMPLEMENTED** (سياسة مكتوبة، لم تُنفَّذ ولم تُختبر).

## المبادئ

1. الواجهة الأمامية **ما بتلمسش** أي مفتاح مزوّد. كل عملية حساسة عبر الـ Backend.
2. `SERVICE_ROLE_KEY` للـ Backend فقط.
3. RLS على كل جدول حساس.
4. فصل صلاحيات العميل عن الإدارة.
5. منع العميل من قراءة بيانات الآخرين.
6. حماية **Registrant Data** (بيانات المالك القانونية).
7. تشفير البيانات الحساسة عند الحاجة.
8. **ممنوع** API Secrets داخل الجداول المكشوفة.
9. **ممنوع** Service Role Key في الـ Frontend.
10. **ممنوع** إظهار Auth Codes إلا لصاحب الدومين بعد التحقق من هويته.
11. Audit Log لكل تغيير حساس.

## مصفوفة الوصول

| الجهة | تستطيع | لا تستطيع |
|---|---|---|
| العميل | قراءة دوميناته وعروضه وطلباته و Webhooks؟ لا | قراءة `provider_costs` أو `pricing_rules` أو بيانات عميل آخر |
| العميل | — | تعديل أسعار البيع · تغيير المالك · رؤية Auth Code لغيره |
| الإدارة | تعديل قواعد التسعير والهوامش | (مقيّدة بـ Audit Log) |

## مخاطر موثّقة

| الخطر | التخفيف |
|---|---|
| IDOR (قراءة دومين عميل آخر) | RLS + تحقق ملكية على كل طلب |
| Privilege Escalation | فصل أدوار + تحقق على الـ Backend |
| تسريب بيانات المالك | تشفير + وصول محدود + تدقيق |
| كشف API Secrets | متغيرات بيئة + Backend فقط |
| تزوير Webhooks | تحقق توقيع + مبلغ + عملة + رقم طلب |
| إساءة استخدام Auth Code | عرض آمن + تحقق هوية + تسجيل |
| تسجيل مكرر | Idempotency + Reconciliation |
| CSRF / XSS / SQLi | حسب طبيعة الواجهات (يُختبر في المرحلة 10) |

## سجل التدقيق (Audit Log) — ضوابط إلزامية

- **Append-only:** `audit_logs` **insert فقط** — `UPDATE`/`DELETE` **ممنوعة** بسياسة صريحة حتى على `service_role`.
- **الصلاحيات:** الكتابة من الـ Backend فقط؛ القراءة **لإدارة فقط**؛ العميل **deny**.
- **يُسجَّل إلزاميًا:** تغيير الأسعار/الهوامش · تغيير الملكية (COR) · التسجيل/التجديد/النقل · **كل ظهور لـ Auth Code** · معالجة Webhooks · تغييرات صلاحيات الأدوار · أي حذف بسياسة الاحتفاظ.
- كل صف يحمل: `actor_type/actor_id` · `action` · `entity_type/entity_id` · `before/after` · `created_at` · `ip` · `reason`.
- **ممنوع** أي تغيير حساس بدون صف تدقيق مقابل. غياب الصف = خطأ أمني.

## حماية Webhooks وProvider Events

- **ممنوع** تخزين بيانات مالك كاملة أو **Auth/EPP Codes** خام في `payment_webhooks` / `provider_events`؛ تُشفَّر أو تُحجب (redaction)، ويُحفظ مرجع بس.
- التحقق من التوقيع إلزامي قبل المعالجة، وكل حدث يُخزَّن حتى لو مكرر/مزيّف لأغراض التدقيق.
- القراءة **Backend/إدارة فقط**؛ العميل **deny**.
