# سيناريوهات فشل الدفع والطلب — Migo Domains

**الوحدة: Payment & Order Engine.** مفيش بوابة دفع إنتاجية دلوقتي. الاختبار كله على Mock.

## السيناريو الطبيعي

```
العميل يختار الدومين → PRICE QUOTE → REGISTRANT PROFILE → PAYMENT
→ PAYMENT WEBHOOK VERIFICATION → AVAILABILITY RECHECK → PRICE RECHECK
→ REGISTRAR REGISTRATION → REGISTRATION CONFIRMATION → CUSTOMER DELIVERY
```

## سيناريوهات الفشل الإلزامية

| # | السيناريو | السلوك المطلوب |
|---|---|---|
| 1 | الدفع فشل | لا تسجيل؛ الطلب يبقى `PAYMENT_PENDING`/`FAILED` |
| 2 | الدفع نجح لكن الـ Webhook تأخر | لا تسجيل قبل التحقق؛ الطلب ينتظر في حالة وسيطة، ولا يُعتمد على إشعار العميل |
| 3 | تكرار الـ Webhook | Idempotency: يُعالج مرة واحدة، والبقية تُتجاهل بأمان |
| 4 | Webhook مزيّف / توقيع غير صحيح | يُرفض؛ يُسجَّل كحدث أمني |
| 5 | الدفع نجح والدومين لم يعد متاحًا | لا تسجيل؛ → `MANUAL_REVIEW` + سياسة استرداد |
| 6 | السعر تغيّر بعد الدفع | لا تسجيل بسعر مخالف؛ → `MANUAL_REVIEW` أو موافقة العميل |
| 7 | Registrar API لم يستجب | لا إعادة عشوائية؛ فحص الحالة (Reconciliation) |
| 8 | Registrar API Timeout مع احتمال نجاح العملية | **ممنوع** إعادة الإرسال قبل Reconciliation — قد يكون الدومين اتسجّل فعلًا |
| 9 | التسجيل فشل بعد تحصيل الأموال | تحديد استرداد أو إعادة محاولة حسب السبب وشروط المزوّد |
| 10 | التسجيل نجح والنظام فشل في حفظ النتيجة | Recovery من سجل المزوّد؛ لا فقدان للحالة |
| 11 | التسجيل نجح وتأخر بريد التحقق | حالة `VERIFICATION_PENDING` وليست `ACTIVE` |
| 12 | عمليتان متزامنتان لنفس الدومين | قفل/Idempotency يمنع التسجيل المزدوج |

## قواعد التنفيذ

- **Idempotency** لكل عملية دفع وتسجيل.
- **ممنوع** إعادة إرسال طلب التسجيل عشوائيًا بعد Timeout.
- **Reconciliation** مع المزوّد قبل أي إعادة محاولة.
- حفظ **كل** الـ Webhooks.
- التحقق من التوقيع والمبلغ والعملة ورقم الطلب.
- منع التسجيل المكرر.
- **ممنوع** إصدار `REGISTERED` بدون إثبات من المزوّد.
- الطلبات غير المؤكدة → `MANUAL_REVIEW`.
- عند تعذّر التسجيل بعد الدفع: سياسة استرداد أو إعادة محاولة حسب سبب الفشل وشروط المزوّد.
- **ممنوع** رد المبلغ تلقائيًا إذا كان من المحتمل أن الدومين اتسجّل فعلًا.

## حالات الدفع

`PENDING` · `PAID` · `FAILED` · `REFUNDED` · `CANCELLED`

> تسجيل الدومين عملية **منفصلة** عن تأكيد الدفع، ولا يُنفَّذ إلا بعد: تأكيد الدفع من الـ Backend، إعادة التحقق من التوفر، صلاحية السعر، صحة بيانات العميل، ورصيد المزوّد (عند مزوّد فعلي).
